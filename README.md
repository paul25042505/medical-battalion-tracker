# medical-battalion-tracker
衛生營車輛人員動態管制系統

## 更新紀錄（RELEASE_NOTES）維護規則

每次版本更新，除了照 `CLAUDE.md` 出貨檢查清單在 `RELEASE_NOTES` 補上當天異動
項目之外，還要做一次精簡整理，避免「關於系統 → 更新紀錄」越堆越長、同一個
功能改了 10 次就有 10 筆內容：

- **同一天同一分類只能有一組**：如果新增內容時發現同一個日期已經有相同
  `category` 的區塊，直接併入該區塊的 `items`，不要另外開一組同名的
  `{ category, items }`。
- **同一個功能反覆修改的過程收斂成最終結果**：像「新增功能 → 發現 bug →
  修一次還是不對 → 再修一次才真的好」這種同一天內針對同一件事的連續調整，
  合併成 1 筆描述「最終呈現的樣子」的項目，不要把除錯過程中的每一步都各自
  留一筆；如果某個功能後來被整個復原（做了又改回原樣），淨效果等於沒有
  對外可見的改變，可以直接省略、不用兩筆都留著互相抵銷。
- **真正不同的事實仍要各自列成獨立項目**：不同功能、不同 bug、使用者會
  感受到的不同層面調整，不要為了精簡而合併成一句話含糊帶過，合併的對象
  僅限於「同一件事的不同修改階段」。
- 每隔一段時間（例如版本主/次號調整、或更新紀錄明顯變得又臭又長時），
  回頭檢視過去幾天的 `RELEASE_NOTES`，用上述規則重新整理一次既有內容，
  不是只處理當天新增的部分。
